# YOLOE Runtime Prompts on RKNN

This reference implementation exports a YOLOE detector with prompt embeddings as a second graph input. It is a proof
of concept for [feature request #25530](https://github.com/ultralytics/ultralytics/issues/25530), not an integrated
Ultralytics export format. The current supported `model.export()` path remains unchanged.

The exported model has a fixed prompt capacity suitable for RKNN static shapes:

```text
images:            float32/uint8 [1, 3, 640, 640]
prompt_embeddings: float32       [1, 8, 512]
```

Text and visual prompt encoders stay on the host. The RK3588 only runs the detector, so a single RKNN model can switch
between text and visual prompts by loading a different small embedding file.

## Scope

- YOLOE-26N/S/M/L/X segmentation checkpoints
- FP16 RKNN on RK3588/RK3588S
- Text prompts generated by `YOLOE.get_text_pe()`
- Visual prompts generated from a reference image and bounding boxes
- CPU postprocessing and NMS
- Optional detection-only ONNX output with `--boxes-only`

Prompt-free checkpoints are deliberately excluded. Their fixed 4585-class classifier produces a
`[1,4621,8400]` output at 640 x 640, and YOLOE-26N measured 3043.61 ms on the test board. Runtime prompts with a small
task vocabulary are both faster and better aligned with this use case.

## Requirements

Export and prompt generation use the normal Ultralytics environment with PyTorch, ONNX, and ONNX Runtime. RKNN
conversion uses a separate environment with `rknn-toolkit2>=2.3.2`. Board inference requires
`rknn-toolkit-lite2`.

`mobileclip2_b.ts` must be available for text prompt generation. Pass its parent directory with `--clip-dir` or place
the file beside the YOLOE checkpoint.

## Export

Export a two-input ONNX graph. Prompt embeddings are fixed to eight rows; unused rows are zero padded later.

```bash
python export.py \
    --weights yoloe-26l-seg.pt \
    --output build/yoloe26l_runtime_prompts.onnx \
    --max-prompts 8
```

The script runs `onnx.checker` and compares every ONNX Runtime output against PyTorch before reporting success.

Convert the graph in the RKNN Toolkit environment:

```bash
python convert.py \
    --onnx build/yoloe26l_runtime_prompts.onnx \
    --output build/yoloe26l_runtime_prompts_fp16.rknn \
    --max-prompts 8
```

Prompt embeddings contain scale-specific YOLOE representation layers. An embedding generated with N weights must only
be used with the N detector, and the same rule applies to S/M/L/X.

## Text Prompts

```bash
python make_prompt.py text \
    --weights yoloe-26l-seg.pt \
    --clip-dir /path/containing/mobileclip2_b.ts \
    --prompts person bus \
    --output build/yoloe26l_person_bus.npz \
    --max-prompts 8
```

The NPZ file stores the padded `[1,8,512]` tensor, active prompt count, and class names.

## Visual Prompts

Coordinates are pixel-space `xyxy` boxes in the original reference image. Multiple boxes can share a class ID.

```bash
python make_prompt.py visual \
    --weights yoloe-26l-seg.pt \
    --image reference.jpg \
    --boxes '120,80,220,210;300,150,380,260' \
    --class-ids 0,0 \
    --names target \
    --output build/yoloe26l_visual_target.npz \
    --max-prompts 8
```

For multiple reference images, generate one normalized embedding per class and image, then average embeddings of the
same class before padding. This was more stable than composing cropped objects into an artificial scene. When visual
classes interfere with each other, run one class embedding at a time and merge postprocessed detections.

## Board Check

Copy the RKNN model, prompt NPZ, this `infer.py`, and a test image to the board, then run:

```bash
python3 infer.py \
    --model yoloe26l_runtime_prompts_fp16.rknn \
    --image bus.jpg \
    --prompt yoloe26l_person_bus.npz \
    --core 0 \
    --warmup 1 \
    --runs 5
```

The result reports `RKNNLite.inference()` latency, output shapes and ranges, finite-value checks, maximum class score,
and candidate count at the requested confidence threshold.

## RK3588S Results

The following FP16 results use RKNN Toolkit 2.3.2, RKNNLite 2.3.0, NPU driver 0.8.8, `bus.jpg`, and `person,bus`
embeddings. Each number is the mean of five Core 0 runs after one warmup.

| Scale     | Mean NPU time | Maximum score | RKNN size |
| --------- | ------------: | ------------: | --------: |
| YOLOE-26N |      75.96 ms |        0.8950 |   8.2 MiB |
| YOLOE-26S |     143.32 ms |        0.9067 |  23.4 MiB |
| YOLOE-26M |     348.29 ms |        0.9233 |  49.9 MiB |
| YOLOE-26L |     393.89 ms |        0.9199 |  59.5 MiB |
| YOLOE-26X |     887.71 ms |        0.9131 | 127.9 MiB |

The N model's maximum PyTorch/ONNX absolute errors were `0.001953125` for detections and `5.36e-06` for prototypes.

## Quantization and Concurrency

FP16 is the reliable default. A 42-pair W8A8 calibration experiment reduced L latency from about 394 ms to 159 ms,
but images with detections in a six-image small-target sample fell from 2/6 to 0/6 and prototype cosine was about 0.706.
Conversion success alone is insufficient to enable INT8.

Assigning one request to all three RK3588 NPU cores did not materially improve latency. Three independent FP16 RKNNLite
contexts pinned to Core 0/1/2 processed three requests concurrently at 6.68 FPS aggregate for the L model, compared with
2.54 FPS for one context. Multi-context scheduling is application policy and is not part of the export graph.

## Known Limitations

- Prompt capacity and image size are static at conversion time.
- Embeddings are not interchangeable between model scales.
- NMS runs outside the RKNN graph.
- Visual prompt extraction still requires the PyTorch checkpoint on a host.
- W8A8 needs a representative accuracy benchmark before deployment.
- The board runtime and driver used for validation are older than the compiler and should be updated for final support.
